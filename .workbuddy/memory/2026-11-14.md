# 2026-11-14

## 需求
隔几天没启动程序，中间交易日的历史数据整段消失。要求启动时先检查哪天漏了，并尝试拉取。

## 实现
- 新增 `gapfill.py`：以指数日K（sh000300）的真实日期作交易日历（排除今天，今天归当日采集），逐源检查最近 20 个交易日的缺口，回补可补的，如实标注不可补的。产出 `snapshots/gap_report.json`（原子写，含 last_recovered，避免次日无缺口时抹掉上次成果）。
- `update.py` 在采集前默认调用 gapfill，新增 `--gap-check` / `--no-gapfill` / `--gap-days N`；`--no-fetch` 跳过联网回补。回补失败只告警，不中断当日更新。
- `export_data.py` 向 data.json 注入精简 `data_gaps`；`index.html` 的历史净申购标题显示「补回 N 天（日期）」「快照缺 N 天（不可补）」。
- README 增补 Layout / Usage / "Automatic gap repair on startup"；update.bat 注释补参数示例。

## 关键边界（勿破）
- 可补：`snapshots/daily/*.json` 日K、`index_daily.json`、上交所 `STAT_DATE` 份额。
- 不可补：`history.json` 盘中快照/5分钟K（日K 不能伪造盘中状态）、深交所历史份额（只有最新一期）、m5 超过约 6.7 个交易日的部分。
- 快照缺口只从 history.json 首份快照之后算；之前是 backfill 的设计，不是漏跑。
- 日K 回补保持原文件起点，只往后追加，避免顺带把历史拉长几十天导致 flow_history 区间起点无故变早。

2026-11-14（周六）启动：补回 11-11/11-12/11-13 三天，24 只日K 刷新、2 天上交所份额补入；净申购可算天数 53 → 56（11-11 +2.802、11-12 −99.754、11-13 −82.127 亿元）。完整 `update.py` 跑通，采集 16.2s、degraded 0；`tests/test_share_flow.py` 5/5 通过；页面 JS 用 node --check 通过。
